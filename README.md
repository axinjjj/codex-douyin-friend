# Codex 抖音好友桥

这是一个公开源码、仅限非商用的实验性桥接项目：本机控制面、状态与临时媒体保持在本地，
回复生成则通过本机启动的 Codex App Server 使用登录账号对应的 Codex 服务。它只面向一个
受信任好友、一个专用抖音账号和一个专用 Edge 配置；陪伴 thread 使用仓库外的专用运行目录，
并要求 App Server 返回的指令来源严格只有私人全局 `AGENTS.md`。本项目并非抖音或 OpenAI 的官方产品，
网页自动化可能随页面更新而需要适配。

## 快速开始

需要 Windows、Node.js 22 或更新版本、已登录的 Codex 桌面应用、Microsoft Edge，以及一个
专门用于桥接的抖音账号。仓库不需要 npm 第三方依赖。

```powershell
git clone https://github.com/axinjjj/codex-douyin-friend.git
cd codex-douyin-friend
npm test
npm run setup:sensevoice
npm run launch:douyin
```

在新开的专用 Edge 中登录抖音，打开要服务的一个聊天，先运行
`npm run probe:douyin` 确认调试连接，再运行 `npm run autostart:install`。首次安装默认只读；
打开 `http://127.0.0.1:43127`，确认页面锁定的是预期聊天后再开启“自动发送回复”。

## 产品契约与代码边界

这座桥的目标不是让 Codex 机械描述媒体，而是让同一个持续上下文里的角色先取得可靠证据，
再像真实看过或听过这次分享一样回应分享意图。当前产品契约固定为八类互不替代的能力：

1. 纯文字进入持久 Codex thread，加载本机私人 `AGENTS.md` 后直接承接对话。
2. 直接发送的相册图片作为本地图片输入同一 thread，再根据图片和上下文回复。
3. 分享视频取得完整可信源时同时处理关键帧和本地音轨；回复分享意图，不输出视频解说稿。
4. 图文、单图和动态图片类作品按实际来源区分；单图仍是完整图文作品，不能误标成封面。
5. 分享评论把评论与它关联的视频或图文一起理解，并保持评论作者与聊天发送者的身份边界。
6. 媒体之前的说明和媒体之后紧跟的附言都进入该媒体的同一个 Codex turn。
7. 启用媒体点赞后，模型只在现有媒体 turn 内决定是否点赞；本端观察到精确回复气泡后才执行原生点赞。
8. 抖音内置表情按消息中的节点顺序作为视觉图片输入；节点标题只作辅助，回复表情传达的聊天语气，
   不把表情逐项复述成图片说明。

代码按这些职责分层：`douyin-inbound-planner.mjs` 负责正常消息分批，并在恢复时用现有 action ID
重建已经提交的首批输入边界，不读取媒体证据；
`douyin-chat-page.mjs` 的静态卡片变体注册表只负责页面识别；
`douyin-media-pipeline.mjs` 的静态媒体适配器只负责把内置表情、直图、作品和评论分派到各自取证链；
`douyin-player-runtime.mjs` 只负责无声打开作品、恢复可信完整源或从 MSE 播放器有界取帧；
图片/视频运行时只负责本地媒体处理；回复生成只接收已经声明边界的证据；发送和断点恢复不读取
媒体实现细节。`douyin-message-quote.mjs` 只负责把已经选定的共享视频绑定到抖音原生引用草稿；
新增抖音结构必须通过显式注册和契约测试进入，运行时不会生成或修改代码。

一个锁定聊天始终绑定一个持久 Codex task/thread。普通消息、媒体、评论和附言都复用它；达到
上下文高水位时在原 thread 内执行官方 compact，不创建侧边栏窗口。只有控制台明确执行“换新
窗口”才创建新 thread，并在新断点提交成功后可恢复地归档旧 thread；失败的新 thread 也会归档。

## 当前阶段

- 已确认抖音 Windows 8.3.0 客户端是 Electron 应用，但它拒绝外部
  `NODE_OPTIONS` bootstrap，也没有开放 CDP 端口。
- Windows UI Automation 只能看到外层 Pane，不能稳定读取聊天内容。
- 当前路线是使用独立 Edge 配置访问 `douyin.com/chat`，再通过仅绑定本机的 CDP 连接。
- Codex 侧使用官方 `codex app-server`，不需要 OpenAI API Key。
- 独立 Edge 配置已经登录；聊天输入区、消息列表和文本气泡的结构已完成只读映射。
- 一次性监听器已经能以方向和哈希指纹比较新消息，仍不会输出聊天正文。
- 一条真实入站文本已经完成 `抖音入站 → Codex App Server → 按 Enter → 本端匹配气泡` 验证；
  这不证明平台业务 ACK 或对端收取。
- 2026-09-05 使用固定测试正文按 Enter 后在本端观察到一次共享视频原生引用气泡，确认出站引用结构和正文可被
  独立哈希；同日又完成一次不按 Enter 的实机门禁，验证引用建立、正文插入、原子所有权校验、
  正文清空和引用关闭。多媒体队列的完整引用发送仍等待下一组真实分享做端到端回归。
- 常驻桥用对端账号的不透明标识生成 SHA-256 会话键，锁定启动时的当前聊天；昵称相同或改名
  不会复用错误的 Codex thread。身份优先读取右侧标题资料；标题区未暴露资料时，只从当前选中
  会话行的头像组件读取 `secUid`。两条路径都只返回哈希，拿不到稳定标识时则拒绝启动。
- 抖音消息 DOM 的倒序排列已改为按视觉纵坐标排序，确保读取最底部的最新消息。
- 入站/出站方向使用消息节点稳定的 `isFromMe` 结构标记，不依赖窗口宽度或左右坐标；专用 Edge
  在后台、最小化或窄窗口下不会再把所有消息误判为居中系统消息。
- 抖音把固定大小的消息 DOM 窗口向前滑动时，桥会用至少两条连续消息的哈希边界重新对齐，
  只处理新露出的尾部消息。旧出站引用在 React 虚拟列表重挂载后可能暂时不再暴露作品目标；只有
  引用正文主指纹和旧卡片指纹都保持一致、且至少两条连续消息共同证明边界时，历史对齐才容忍这项
  可选证据单边消失。发送确认、待处理消息重绑和崩溃恢复仍要求精确目标，找不到可靠边界时仍会安全停机。
- 桥在启动、轮询、静默合并和本端出站气泡核验前都会通过页面 DOM 有界滚到消息尾部，不依赖人工点开
  Edge 或点击最新消息；它不会因此恢复一个被用户主动最小化的窗口。
- 分享作品的媒体指纹优先在页面内读取 React `itemId`/`item_id` 或 schema，再只把不可逆哈希写入
  断点；动态卡片文案、时间标签和点赞面板都不参与指纹，避免同一作品渲染变化后破坏恢复边界。
- 检测到新入站后会等待一个最长 2.25 秒、以 750 毫秒静默为结束条件的短合并窗口。之后按
  消息时间顺序建立最多 12 条的持久队列：第一条媒体前的连续文字，以及每条媒体后紧跟的连续
  文字，都会和对应媒体进入同一个 Codex turn；相邻媒体仍逐条处理，纯文字批次仍合成一个 turn。每条回复在本端 DOM 观察到精确出站气泡后才
  推进该项断点；异常或重启会保留尚未完成的哈希队列，不会重发已经观察到本端气泡的前项回复。若旧回复
  已经生成而后续新消息才抵达，恢复时会用旧 action ID 在有界队列中唯一核验原输入前缀；旧回复只
  消费该前缀，后到消息继续留在后续批次。无法证明唯一边界时会保留旧 action 与 turn 凭据并安全停止。
- 无法归类的一条左侧入站只推进为“已跳过”，不会让同批或之后的纯文字、图片和作品一起停住；
  已登记的平台系统卡只更新快照，未确认的右侧内容则持久化进入暂停发送、继续监听的降级态。
  只有可识别的出站账目矛盾、聊天身份或消息边界异常才按原有安全门禁停止。处理中断的旧版空文字表情
  可通过仅限该结构的旧指纹别名迁移为现役表情媒体，后续文字仍留在队列中。
- 完整识别为视频、且两侧都能取得唯一作品身份哈希的共享作品批次，发送前会重新确认该批对应的
  精确媒体指纹和当前序位，再通过唯一可见的“回复”菜单建立抖音原生引用。引用草稿以 action ID
  派生的确定性 nonce 绑定到该媒体节点，进程中断后只接管正文、目标和 nonce 全部一致的自有草稿；
  编辑器非空时不会覆盖现有草稿。发送日志落盘后、真正按 Enter 前会再次用同一原子门禁校验聊天、
  编辑器正文、引用预览和媒体节点；这次校验失败会把动作安全退回待发送且绝不按 Enter。恢复时也会
  在推进本端气泡已观察断点前幂等清理精确的旧引用，无法证明所有权时只停止、不关闭用户后来打开的引用。
  普通文字、直接相册图片、图文和评论分享
  不走这条引用路径；无法取得唯一作品身份的共享视频保留原有无引用回复，不会因此丢回复。
  已进入引用路径后，菜单、草稿或目标有歧义时不会退化为无引用发送。带引用回复除独立正文哈希外
  还持久化作品身份哈希，因此同文回复引用错视频也不能通过发送或重启恢复校验。
- 每个会话键对应一个持久 Codex thread。进程重启后优先通过 `thread/resume` 恢复；成功恢复时
  不重复注入历史，新建或安全回退 thread 时才注入一次当前可见聊天记录。新 thread 在人设校验、
  历史注入或首次状态提交前失败会被可恢复归档；显式换新 thread 也只在新断点提交成功后归档旧
  thread，避免失败测试不断堆出侧边栏窗口。持久 thread 在开始接收新 turn 前会通过官方
  `thread/name/set` 固定为不含聊天正文的通用标题，侧边栏不会再拿第一条私聊提示当任务名。
- 每个新 thread 都有递增代际；旧代异步结果不能在新 thread 上启动 turn。每个入站批次另有一份
  只含哈希、turn ID 和阶段的副作用日志。`turn/start` 返回后会先完成真实 turn ID 的持久化屏障，
  屏障期间到达的完成通知按顺序缓存；若超时或 App Server 退出发生在写入已经开始之后，会等该次
  写入收口再释放调用者，避免旧阶段稍后覆盖新阶段。实时完成与重启后的 `thread/read` 使用同一个
  有界选择器，以 `item/completed` 的唯一 `final_answer` 为准，绝不把 commentary 混入抖音回信；
  多个 final、只有 commentary 或现代结构化流缺少 completed item 都会停止。App Server 主动发来的
  带 ID 请求也会与客户端响应分流并明确拒绝，不会默认授予工具、文件或权限。重启可按 turn ID 取回
  已完成回复，Enter 后则先验证出站指纹，只恢复未执行的后置动作；没有 turn ID 的不明启动、无法
  验证的发送和已经记录尝试的点赞都不会靠猜测重做。
- 默认固定使用 `gpt-5.6-sol`、`xhigh`。陪伴 thread 的 `cwd` 固定在
  `%LOCALAPPDATA%\CodexDouyinFriend\companion`，启动和恢复都会校验实际模型、持久属性，
  并要求 `instructionSources` 按顺序严格等于私人全局 `AGENTS.md`；额外仓库规则、重复来源、
  相对路径或顺序变化都会拒绝继续。既有 thread 只有通过这项精确检查才会保留，否则走安全换新流程。
- 常驻桥按 App Server 的 `thread/tokenUsage/updated` 实际用量自动调用官方
  `thread/compact/start`：默认在当前上下文达到模型窗口 75% 时压缩，降到 50% 后重新武装，
  两次阈值触发的尝试至少间隔 5 分钟。
- 压缩只会在没有 Codex turn、媒体处理或发送操作的空闲点启动，并等待官方
  `contextCompaction` item 和对应 turn 都完成；`contextWindowExceeded` 最多执行一次压缩和
  一次原输入重试，不会形成循环或重复发送。
- 旧版 `.MessageItemShareAwemecontainer` 与新版 `.BulletBulletVideocontainer` 分享卡由同一份
  可扩展变体注册表识别；React 数据中的 camelCase/snake_case 字段都受支持。视频卡片已经完成
  真实入站、模型生成、按 Enter 与本端匹配气泡验证：桥从当前登录态读取有界的兼容播放候选，
  优先通过抖音官方播放入口取得新鲜 CDN 地址；下载先用 1 字节探测总大小，再按 1 MiB Range
  最多三路并发接收，逐段校验位置和总长度后按原顺序写入。单段失败最多重试 3 次，只有完整分段才写入文件；重试会
  回到官方入口刷新 CDN 地址。详情对象按媒体语义键优先遍历，不会再因 `video` 排在大型对象
  的第 80 个普通字段之后而漏掉 H.264。下载成功后还必须由临时 Edge 媒体页实际解码；只有明确的解码
  不兼容才清理该候选的文件并尝试下一可信候选，下载与解码共用六分钟总预算，场景处理等其他
  错误不会被换源掩盖。解码就绪必须同时具有有效时长和至少 `2×2` 的视频尺寸；最终 PNG 的
  IHDR 尺寸和浏览器画布像素统计必须一致。没有成功呈现帧、尺寸无效或 PNG 不一致仍是解码失败；
  已成功呈现且像素统计有效的全黑画面则保留为 `decoded-black` 证据，明确禁止据此编造不可见内容，
  不会再把合法黑场误判成坏视频。所有完整视频候选都以明确的来源缺失、解码不可用或限时内无帧
  失败且存在可信封面时才降级为
  `shared_cover`。之后按时长自适应抽取关键帧，以 `localImage` 输入同一个 Codex thread。
  作品详情读取的页面内请求与外层 15 秒 CDP 预算相互兼容；跳转目标仍必须属于受信任
  媒体域名。若详情和 React 数据确实只给封面，桥还会精确重认该消息，在 4 秒有界预算内点击
  已登记卡片的真实 React 播放目标。播放动作前会同步安装静音保护，并用一次性动作标记绑定
  “精确消息 → 新打开查看器 → 新出现的视频元素”；页面上同时出现但不属于该查看器的网络视频
  不再作为这条消息的来源。查看器自身暴露可信 HTTPS 源时继续走原有视频下载、关键帧和音轨链；
  若播放器只暴露 `blob:`/MSE，则直接在仍被静音的可见播放器内
  有界扫描和截取关键帧；这条兜底明确标为无音轨的纯视觉证据。两条路径都失败时才诚实保留
  `shared_cover`，查看器和静音保护都会在离开取证层前关闭并撤销。
- 30 秒内短视频预算为 5 帧，随后按时长升到 8/12/16 帧，长视频硬上限为 18 帧；
  场景扫描最多取 72 个低分辨率 RGB 签名，保留首尾、时间覆盖、场景变化和可信音频锚点，
  去除相似的中间帧。寻帧后优先等待浏览器的实际视频帧呈现回调，再读取画布。
- 低分辨率扫描只在临时 localhost Edge 媒体页内顺序执行并保存在内存；磁盘只写最终
  入选的 PNG，不批量落盘缩略图。
- 音轨通过同一个一次性 `127.0.0.1` 媒体页由专用 Edge 解码成 16 kHz 单声道 WAV，
  再由本机 SenseVoiceSmall Q8 识别台词、语言、情绪和声音事件；不依赖 FFmpeg 或 Python。
  SenseVoice 是可选能力：运行包缺失或校验失败时，桥仍可启动并明确按纯视觉处理视频，控制台
  显示安装命令，不会把启动失败伪装成已经听过音轨。
- 固定 SenseVoice 运行包已验证支持 FSMN-VAD SRT；严格解析成功时，语音段、情绪和声音
  事件变化附近的画面会进入统一候选预算。自定义旧运行时不支持 SRT 时仍保留普通转写但
  不产生时间锚点；声明支持却输出非法 SRT 时丢弃该次音频理解，按纯视觉选帧，绝不根据
  文字长度猜时间。
- 关键帧、音频转写和当前聊天上下文会进入同一个 Codex turn；临时媒体页始终作为隐藏的后台目标创建，
  不出现在标签栏、不抢占抖音聊天页，处理后自动关闭。页面内部只模拟解码所需的焦点状态，
  不会激活真实标签或浏览器窗口。
- 本地 supervisor 负责专用 Edge、桥进程、退避重启和安全停机。bridge 退出前只发布严格白名单的
  `retry`、`recover` 或 `block` 终止原因，原因、阶段与处置必须满足固定组合，supervisor 还会核对退出码，
  不把 stderr、聊天正文或本地路径写进状态。空闲态瞬时异常按
  2/5/15/60 秒退避，达到窗口预算后仍以 60 秒封顶低频恢复，不会仅因重试次数永久下线；可靠边界
  缺失、损坏或无法唯一恢复的持久状态会一次性停止。已持久化的队列或明确的编辑器/引用 UI 所有权波动可以恢复，
  未证明安全的理解、压缩、待发或发送阶段异常仍保持人工处理。
- 专用 Edge 外框已经恢复但渲染视口仍卡在最小化尺寸时，桥会用一次有界的 1 像素窗口变化
  刷新渲染面；真正处于最小化状态时不会擅自把窗口弹出来。

## 隐私边界

- 不读取、复制或提交手机号、验证码、Cookie、Token。
- `private/` 永远不进入 Git；实时桥不会把私人全局人设复制到仓库。
- 调试输出默认不打印聊天标题、消息正文或页面 URL。
- 在本项目自身的存储边界内，消息正文、音轨转写和模型回复只在进程内存中传递，不写入项目
  日志或桥状态文件；这不等于它们只在本机处理。
- 分享评论的作者名、正文和关联作品标题同样只在当前进程内存与 Codex turn 中传递，不写日志或断点。
- 媒体点赞决策使用每个 turn 随机生成的短期 nonce 控制标记；标记会在发送前剥离，不写日志，
  页面动作日志只记录已应用、已跳过或校验失败。
- 会话映射与消息断点只写入被 Git 忽略的 `.runtime/douyin-bridge-state/v1/`；每个会话保留
  主快照和恢复快照，内容仅含版本、会话键、Codex thread ID、thread 代际、模型配置、阶段、
  消息指纹和副作用日志中的哈希/turn ID/动作状态；不保存 prompt、回复正文或媒体地址。
  两份快照都损坏或断点含义不明确时会停止，绝不靠猜测推进。
- 当前实现固定使用持久 Codex task/thread：聊天正文、媒体转写、模型回复及人设会作为模型输入
  进入 Codex 服务，并保留在登录账号的任务历史中，受该账号的产品数据与保留设置约束。桥接
  项目不会再把正文复制到 `.runtime`，但目前也没有“处理完即删除”的临时 thread 模式。
- 上下文压缩日志只包含事件、触发原因、状态、数值用量和安全协议错误码；不包含聊天正文、
  人设内容、Cookie 或 Token。压缩失败、超时或服务端不支持时，桥保留当前 thread 并继续监听。
- 视频播放地址不写日志；下载视频、WAV 音轨与关键帧只进入被 Git 忽略的
  `.runtime/video-analysis/`，Codex turn 完成后删除。
- 聊天图片内嵌解码/下载/截图、内置表情转换、分享封面和图文作品图片只进入
  `.runtime/image-analysis/`，同样在 Codex turn 后删除；只允许受信任的抖音/字节媒体域名，
  内置表情单图最多 4 MiB，其他图片单图最多 8 MiB，单次合计最多 64 MiB。
- 正常完成或报错都会立即清理当次媒体任务；进程被强杀后遗留的 UUID 任务目录会在下次
  启动时清掉（只处理超过 2 小时的目录，避免碰到仍在运行的任务）。
- SenseVoice 程序与模型只保存在被 Git 忽略的 `.runtime/tools/sensevoice/`；安装脚本固定
  官方版本与 SHA-256，语音不会发往在线转写服务。
- 实时桥只服务启动时的当前聊天；检测到聊天对象变化时立即停止。
- supervisor 日志只写脱敏状态，单文件达到 1 MiB 后轮换，最多保留当前与上一份日志。
- 未知媒体日志只允许结构签名、元素计数、通用类名提示和属性名；正文、URL、账号、作品号及
  DOM 属性值不会进入日志。
- 发送必须由控制台在当前只读桥已经返回“聊天哈希 + CDP target + 页面代际”的绑定后启用。
  桥在写编辑器前和按 Enter 前都会重新验证整份绑定；页面刷新、target 更换或聊天对象变化会撤销
  发送授权并安全停机。默认只读模式只报告新活动，不生成回复，也不推进持久消息断点，因此之后
  重新授权发送时仍能处理断点后的消息。

## 尚未解决的发布边界

- 自动发送仍是默认关闭的实验能力，只适合一个受信任好友与专用账号。Codex App Server 以当前
  Windows 用户和仓库外的陪伴运行目录运行；项目尚未提供操作系统级沙箱或可验证的能力声明，不能证明
  运行中的编码代理绝对无法访问同一用户可读的其他文件。
- 抖音网页没有给桥暴露经验证的稳定消息 ID。当前去重与恢复依赖最多 12 条可见 DOM 消息的
  内容指纹、方向和连续重叠边界，不是独立的持久收件箱；检测到边界缺失或页面结构变化时会
  安全停机，但窗口外的不同历史可能收敛为同一有限快照而无法被检测，不能承诺持续收件或绝不漏收。
- `reply-latest-douyin-message.mjs` 与 `reply-latest-douyin-video.mjs` 只生成脱敏诊断结果，已删除
  环境变量发送分支，并与主桥共用同一聊天运行锁。`sendAndVerifyDouyinReply` 的聊天能力、停止门和
  两个 journal 回调全部为必填；生产发送调用者只剩主桥。可选点赞在 Enter 前重绑定到当前媒体
  occurrence，多次恢复累计位置变化；目标滑出窗口或证据不足时只终结点赞，不影响已确认回复和队列。
- `send-verified` 只证明当前本端 DOM 出现了精确出站指纹，不等于抖音业务层 ACK 或收件端已经收到；
  Enter 是否生效不明时仍拒绝盲目重发。
- 当前每个聊天键使用一个持久 Codex task/thread，并不提供真正的临时会话生命周期。桥内显式
  “换新窗口”会在新断点可靠提交后把旧 thread 归档，失败的新建 thread 也会归档；归档不是永久
  删除，需要彻底删除已保留上下文时仍必须在 Codex 产品侧管理相应任务。

## 本地验证

```powershell
npm test
npm run smoke:codex
npm run setup:sensevoice
npm run probe:sensevoice
npm run launch:douyin
npm run probe:douyin
npm run inspect:douyin
npm run discover:douyin-chat
npm run snapshot:douyin-chat
npm run watch:douyin-chat
npm run watch:douyin-media
npm run probe:douyin-video-media
npm run probe:adaptive-video
npm run test:douyin-editor
npm run diagnose:douyin-chat
npm run diagnose:douyin-video
npm run bridge:douyin-chat
npm run supervisor:douyin
npm run autostart:install
npm run autostart:remove
```

`smoke:codex` 会创建临时持久 Codex thread、设置并核对固定无内容名称、读取已完成 turn、
关闭首个 App Server 客户端再恢复它，并确认测试目录里的 `AGENTS.md` 同时满足：

1. 出现在 App Server 返回的 `instructionSources` 中；
2. 实际改变模型回复；
3. 恢复后的同一 thread 仍加载该指令并能继续对话。

冒烟结束会删除该测试 thread。这个检查同时覆盖桥在崩溃恢复中依赖的 `thread/read`，以及
持久桥任务避免泄露首条聊天内容所依赖的 `thread/name/set`。

首次启用视频音轨前运行 `npm run setup:sensevoice`。它会把官方 SenseVoice llama.cpp
Windows CPU 运行包、SenseVoiceSmall Q8 和 FSMN-VAD 下载到 `.runtime` 并逐一校验
SHA-256；约占 262 MB 模型与压缩包空间。`npm run probe:sensevoice` 使用官方公开中文
样本做本地转写，只输出字数和标签，不打印识别正文。

`probe:douyin` 只检查 `127.0.0.1:9229` 是否存在浏览器调试目标，不读取页面内容。

`probe:douyin-video-media` 只输出文件大小、时长、尺寸、抽帧/黑帧计数、音轨可用性、本地转写长度和清理结果；
成功结果会在打印前删除本次 UUID 媒体目录，不输出聊天正文、作品号或媒体地址。

`probe:adaptive-video` 不读取抖音聊天，也不发送消息。先设置
`CODEX_DOUYIN_VIDEO_FIXTURE` 为不超过 100 MB 的非敏感本地 H.264 MP4，再运行该命令；
它只输出时长、预算、扫描/入选数量、总图片大小、耗时和清理结果，并在结束时删除整个
UUID 媒体任务目录。按项目门禁，任何 CDP 媒体检查前都先运行 `npm run probe:douyin`。

`launch:douyin` 使用 `.runtime/edge-profile` 创建专用浏览器配置，并把调试端口绑定到
`127.0.0.1`。第一次打开时用抖音客户端扫码登录专用小号；Cookie 只保存在被 Git
忽略的本地配置目录。`inspect:douyin` 只返回控件数量和页面就绪状态，不会输出标题、
URL、昵称或消息正文。

`discover:douyin-chat` 只返回控件层级与 CSS 结构提示；`snapshot:douyin-chat`
只返回消息方向、类型、长度和不可逆哈希指纹；`watch:douyin-chat` 在当前聊天上等待一条
新的左侧入站消息。三者都不会把消息正文写入终端或文件。

`diagnose:douyin-chat` 与 `diagnose:douyin-video` 会取得和实时桥相同的聊天运行锁，在仓库外的
陪伴运行目录创建一次性 thread，只输出生成与媒体证据统计，永远不写编辑器或按 Enter。

Chat 页的 Slate 输入框选择器参考并在当前页面实测了 MIT 许可项目
[ScriptCat-Douyin-Fire-Helper](https://github.com/dr-190/ScriptCat-Douyin-Fire-Helper)。

## 启动实时桥

先保持专用 Edge 窗口停留在要服务的聊天，然后执行：

```powershell
$env:DOUYIN_SEND_ENABLED = "true"
$env:DOUYIN_BRIDGE_TIMEOUT_MS = "3600000"
$env:CODEX_DOUYIN_TURN_TIMEOUT_MS = "1800000"
$env:CODEX_DOUYIN_MODEL = "gpt-5.6-sol"
$env:CODEX_DOUYIN_EFFORT = "xhigh"
npm run bridge:douyin-chat
```

Codex 单个 turn 默认等待 30 分钟，而不是旧版的 120 秒；可通过
`CODEX_DOUYIN_TURN_TIMEOUT_MS` 在 5 到 60 分钟之间覆盖。这个上限从发起
`turn/start` 请求时开始计算；该请求自身另有 30 秒客户端上限。视频下载、解码、抽帧和
本地转写仍使用各自的媒体预算。
桥会持续读取 App Server 事件，直到收到该 turn 的 `turn/completed`，避免较慢的
多模态输入或 `xhigh` 推理被本地客户端提前中断。

上下文压缩默认参数可按需覆盖：

```powershell
$env:CODEX_DOUYIN_COMPACTION_HIGH_WATERMARK = "0.75"
$env:CODEX_DOUYIN_COMPACTION_LOW_WATERMARK = "0.50"
$env:CODEX_DOUYIN_COMPACTION_COOLDOWN_MS = "300000"
$env:CODEX_DOUYIN_COMPACTION_TIMEOUT_MS = "120000"
```

高低水位必须满足 `0 <= low < high <= 1`。策略使用
`tokenUsage.last.totalTokens / modelContextWindow` 作为当前上下文占比；
`tokenUsage.total.totalTokens` 是累计用量，不参与阈值判断。

首次启动时，既有可见文本会作为新 Codex thread 的上下文但不会补回；以后启动会恢复该
聊天对应的 thread，并从持久消息断点继续。停机期间的新入站只有仍落在最新 12 条可见窗口内、
且旧新快照之间存在可证明的连续重叠边界时，才会按时间顺序进入同一条持久队列；多条连续文本
会合并为一个 turn，多个媒体则逐条生成回复并核验本端出站气泡。处理视频或转换内置表情 WebP 时，专用 Edge 会在后台创建不可见的
本机临时媒体页，依次完成所需的格式转换、音轨解码/本地转写、低分辨率场景扫描或最终帧抽取，
随后关闭精确的临时目标；不会切走聊天标签或恢复已最小化窗口。图片和转写仍进入
同一个 Codex turn。无音轨或转写失败时会明确降级为只看画面，不会假装听见声音；超过
15 分钟的视频为避免整轨解码造成无界内存，不处理音轨，只做有界画面分析。每次启动只锁定
一个聊天；对方切换、输入不完整、本端已承诺气泡无法核验、出现额外可识别出站，或系统检测到新增消息
缺少 12 条窗口内的可靠边界时会停止，不会盲目重发。未确认的右侧内容先暂停发送并继续监听，快照稳定且
出站账目重新对平后自动恢复。不同的窗口外历史可能最终呈现相同的有限哈希
快照，这种情况下桥无法知道曾经滑窗，仍可能漏收；项目不承诺持续或耐久收件。桥接进程用 Windows 命名管道保证同一会话
只有一个实例；进程被强制终止后，操作系统会自动释放该锁。

日常使用不需要直接启动桥，运行 supervisor 即可：

```powershell
npm run supervisor:douyin
```

然后打开 `http://127.0.0.1:43127`。supervisor 首次启动沿用默认
`gpt-5.6-sol / xhigh`，自动发送和媒体点赞默认关闭；修改后的模型、思考强度、自动发送及
媒体点赞开关只保存到被 Git
忽略的 `.runtime/supervisor/config.json`。点击“换新窗口”会新建持久 Codex thread，给它补入
当前可见文本历史，并在新状态提交成功后归档旧 thread；若上次在人设校验、历史注入或首次状态
提交前失败，新建但未使用的 thread 也会归档。若上次在理解或回复待发阶段中断，只有这个显式动作会在消息边界完全吻合时
回退断点并重做一次。多媒体队列中，待处理媒体后面已有前一项的已确认回复时，会在完整快照
一致的前提下按指纹重新绑定原媒体位置；发送中或聊天已变化时仍拒绝恢复。

安装当前 Windows 用户登录后的自启动：

```powershell
npm run autostart:install
```

任务名固定为 `CodexDouyinFriendSupervisor`，使用交互式当前用户、最低权限，并由任务计划程序
直接托管隐藏的 Node supervisor 主进程；
supervisor 自身异常由任务计划程序最多重启 3 次；桥的普通空闲异常使用 2/5/15/60 秒退避，10 分钟
窗口内达到 6 次后保持每 60 秒一次的低频恢复，而不是永久进入 `blocked`。明确的安全歧义不参与
自动重试。卸载自启动使用 `npm run autostart:remove`；它只删除这一个任务，不删除浏览器登录态、
模型或对话断点。Codex 桌面版更新后若其内置 `codex.exe` 路径发生变化，重新运行同一个安装命令
即可刷新任务中的精确路径，不需要先卸载，也不会清除桥状态。

当前运行路线是抖音网页版，因此不能真正“锁死”抖音服务端页面版本，也不应通过关闭 Edge
安全更新来换取稳定。专用 Edge 配置减少了扩展和账号环境变化；页面结构发生变化时，哈希断点、
聊天锁和本端出站气泡核验会让桥安全停机，等适配后再由控制台明确重连。

媒体边界固定为：视频最多 100 MB；音频最多 15 分钟、WAV 最多 40 MiB；场景扫描最多
72 个 16×10 RGB 签名并限时 45 秒；最终最多 18 张图片、每边不超过 768 像素、单张最多
4 MiB、合计最多 64 MiB，并另设 45 秒抽取时限。视频候选共用 6 分钟下载上限，单个请求
连续 30 秒无数据才判为静默失败；浏览器处理和本地转写也各自有超时。音频页若超时会被
关闭并以全新的临时页继续纯视觉处理。

主状态快照损坏但恢复快照有效时，会保留旧消息断点、改建新 thread，并只补注入非待处理
历史；服务端 thread 缺失或与当前模型配置不兼容时同样安全回退。若中断发生在已记录 turn ID
之后，下一次启动只会从同一 thread 按 ID 读取完成结果并校验摘要；Enter 已尝试时只凭精确出站
指纹确认，不会重发。`turn/start` 未能留下 ID、发送结果无法确认、DOM 边界变化或代际不一致时
仍保持失败关闭，等待人工判断。

SenseVoice 使用 [QwenAudio/SenseVoice](https://github.com/QwenAudio/SenseVoice) 官方发布的
本地 llama.cpp / GGUF 运行时；Codex App Server 当前只接收文本和图片，因此音频先在本机
转成文字与标签，再连同关键帧送入 Codex。

## 人设目录

仓库里的 `fixtures/persona/AGENTS.md` 只是无敏感内容的加载测试。正式运行时直接使用
Codex 已有的私人全局人设：

```text
%USERPROFILE%\.codex\AGENTS.md
```

桥在每次启动或恢复时要求 App Server 的 `instructionSources` 按顺序严格只有这一个绝对路径；
缺失、额外、重复、相对或顺序变化都会拒绝回复。正式 thread 的 `cwd` 位于
`%LOCALAPPDATA%\CodexDouyinFriend\companion`，不再让仓库 `AGENTS.md` 进入陪伴指令链。
人设内容不会复制进此仓库，日志也只报告检查真假和来源数量，不输出私人路径。
